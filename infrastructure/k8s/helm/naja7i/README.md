# naja7i Helm chart

Umbrella chart deploying the NAJA7I-APP platform (13 Spring Boot
microservices + React frontend) on Kubernetes. Bitnami subcharts provide
in-cluster Postgres / MongoDB / Redis / Kafka / MinIO for dev/staging; in
production they are typically disabled in favour of managed services.

## Layout

```
helm/naja7i/
├── Chart.yaml                     dependencies on Bitnami postgres/mongo/redis/kafka/minio
├── Chart.lock                     generated by `helm dep update` (do NOT hand-edit)
├── values.yaml                    canonical defaults
├── values-dev.yaml                kind/k3d single-node overrides
├── values-staging.yaml            managed-DB overrides + LE staging
├── values-prod.yaml               managed everything + HPA/PDB + LE prod
├── files/postgres-init.sh         shipped into the postgres subchart as a ConfigMap
└── templates/
    ├── _helpers.tpl
    ├── NOTES.txt
    ├── serviceaccount.yaml
    ├── configmap-common.yaml      shared env (Eureka URL, Kafka bootstrap, ...)
    ├── configmap-postgres-init.yaml
    ├── secret-placeholder.yaml    DEV-ONLY; replace with sealed-secrets for prod
    ├── deployments.yaml           iterates over .Values.services + frontend-web
    ├── services.yaml              ClusterIP Service per Deployment
    ├── hpa.yaml                   HPA only for services with .hpa.enabled
    ├── pdb.yaml                   PDB only for services with .pdb.enabled
    ├── ingress.yaml               single Ingress: frontend / + gateway / + /ws
    ├── certificate.yaml           cert-manager Certificate for the two hosts
    └── networkpolicy.yaml         default-deny + allow rules (opt-in)
```

## First-time install

```bash
# 1. Resolve subchart dependencies (writes Chart.lock + charts/*.tgz)
helm dependency update infrastructure/k8s/helm/naja7i

# 2. Lint with each env file (catches missing required fields)
helm lint infrastructure/k8s/helm/naja7i -f infrastructure/k8s/helm/naja7i/values-dev.yaml
helm lint infrastructure/k8s/helm/naja7i -f infrastructure/k8s/helm/naja7i/values-staging.yaml
helm lint infrastructure/k8s/helm/naja7i -f infrastructure/k8s/helm/naja7i/values-prod.yaml

# 3. Dry-run template
helm template naja7i infrastructure/k8s/helm/naja7i -f infrastructure/k8s/helm/naja7i/values-dev.yaml \
  | less

# 4. Install (dev cluster)
helm upgrade --install naja7i infrastructure/k8s/helm/naja7i \
  --namespace naja7i --create-namespace \
  -f infrastructure/k8s/helm/naja7i/values-dev.yaml
```

## Upgrade

```bash
helm upgrade naja7i infrastructure/k8s/helm/naja7i \
  -n naja7i \
  -f infrastructure/k8s/helm/naja7i/values-prod.yaml \
  --set global.imageTag=$(git rev-parse --short HEAD)
```

## Per-environment matrix

| Concern             | dev                       | staging                    | prod                        |
|---------------------|---------------------------|----------------------------|-----------------------------|
| replicas (typical)  | 1                         | 1-2                        | 2 (HPA-driven up to 8)      |
| HPA                 | OFF                       | OFF (cost)                 | ON                          |
| PDB                 | OFF                       | payment only               | gateway, auth, payment, eureka |
| NetworkPolicy       | OFF                       | ON                         | ON                          |
| TLS                 | OFF                       | Let's Encrypt staging      | Let's Encrypt prod          |
| postgres subchart   | in-cluster (5Gi)          | OFF (managed)              | OFF (managed)               |
| mongodb subchart    | in-cluster (5Gi)          | in-cluster (10Gi) or Atlas | OFF (Atlas)                 |
| redis subchart      | in-cluster (2Gi)          | OFF (ElastiCache)          | OFF (ElastiCache)           |
| kafka subchart      | in-cluster (5Gi)          | OFF (MSK)                  | OFF (MSK)                   |
| minio subchart      | in-cluster (5Gi)          | in-cluster or S3           | OFF (S3)                    |
| placeholder Secret  | enabled                   | disabled (sealed-secrets)  | disabled (sealed-secrets)   |

## Secrets

`naja7i-secrets` must contain at least the following keys:

| key                              | description                                          |
|----------------------------------|------------------------------------------------------|
| `jwt-secret`                     | HMAC signing key, ≥32 chars                          |
| `internal-key`                   | shared internal service-to-service header            |
| `postgres-password`              | DB password for the `naja7i` Postgres user           |
| `mongodb-password`               | password for the `naja7i` Mongo root user            |
| `redis-password`                 | optional; empty if `auth.enabled=false`              |
| `minio-password`                 | MinIO root password / S3 secret access key           |
| `anthropic-api-key`              | Claude API key for ai-agent-service                  |
| `twilio-auth-token`              | SMS / WhatsApp (notification-service)                |
| `sendgrid-api-key`               | email driver (notification-service)                  |
| `livekit-api-secret`             | video-session-service room tokens                    |
| `firebase-service-account-json`  | push notifications service account JSON              |

In dev the chart can render a placeholder Secret with these keys
(`placeholderSecret.enabled: true`). In staging/prod that flag is set to
`false` and the real Secret is created out-of-band via
[kubeseal](../../sealed-secrets/README.md).

## Service map

Every entry in `.Values.services` produces:
- a `Deployment` with liveness + readiness probes on `/actuator/health`
- a `ClusterIP` `Service` exposing the configured port
- optionally an `HorizontalPodAutoscaler` (when `.hpa.enabled`)
- optionally a `PodDisruptionBudget` (when `.pdb.enabled`)

The 13 backend services are:

| name                   | port  | replicas (default) | HPA  | PDB  |
|------------------------|-------|--------------------|------|------|
| config-server          | 8888  | 1                  | no   | no   |
| service-discovery      | 8761  | 1                  | no   | no   |
| api-gateway            | 8080  | 2                  | yes  | yes  |
| auth-service           | 8101  | 2                  | yes  | yes  |
| user-profile-service   | 8102  | 2                  | yes  | no   |
| calendar-service       | 8103  | 1                  | yes  | no   |
| pricing-service        | 8104  | 1                  | yes  | no   |
| booking-service        | 8105  | 2                  | yes  | no   |
| payment-service        | 8106  | 2                  | yes  | yes  |
| chat-service           | 8107  | 2                  | yes  | no   |
| video-session-service  | 8108  | 1                  | yes  | no   |
| ai-agent-service       | 8109  | 1                  | yes  | no   |
| notification-service   | 8111  | 2                  | yes  | no   |

plus `frontend-web` (port 80, nginx).

PDB is enabled on the three SPOFs: the gateway (only ingress entry-point),
auth-service (sign-in path required for everyone), and payment-service
(money-critical, slow boot, never want to be down to zero pods).
